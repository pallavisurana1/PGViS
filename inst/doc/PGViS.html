Scoring regulatory germline variant burden with PGViS

What the score is measuring

A germline variant that lands inside a splice donor site or a transcription factor binding site may or may not break it. PGViS asks a model trained on that class of element to score the reference sequence and the mutated sequence, and treats a large drop in confidence as evidence of disruption.

That alone does not distinguish a variant that is disruptive from one that is disruptive and enriched in your cohort. So PGViS also compares the cohort allele frequency against a matched population frequency. The composite pulls these together into one number per sample.

Three components:

# strongly disruptive: model is confident before, not after
log_odds_ratio(p_ref = 0.97, p_alt = 0.03)
#> [1] 10.0299
score_change(0.97, 0.03)
#> [1] -0.9118

# a variant enriched in the cohort relative to the population
d <- data.frame(af_ref = 0.60, af_alt = 0.40,
                pop_af_ref = 0.95, pop_af_alt = 0.05)
pgvis_delta_wi(d, transform = FALSE, keep_raw = TRUE)[, c("delta_af_alt", "delta_wi")]
#>   delta_af_alt delta_wi
#> 1         0.35 7.368281

score_change deliberately shrinks toward zero when the model is unconfident either way:

c(confident = score_change(0.9, 0.7), unconfident = score_change(0.3, 0.1))
#>   confident unconfident 
#>       -0.18       -0.06

Both pairs differ by 0.2 in probability, but only the first is a change the model actually stands behind.

Coordinate keys

Joins between the variant table and the prediction table are the place where this kind of pipeline usually goes wrong, because the two sides get built by different scripts with different key formats. PGViS has one constructor each, and they round-trip:

k <- func_site_key("chr7", 55019000, 55019080, "-")
v <- variant_key("chr7", 55019032, 55019033, "a", "g")
c(k, v)
#> [1] "chr7:55019000-55019080(-)"   "chr7:55019032-55019033(A>G)"
parse_key(v, "variant")
#>    chr    start      end ref alt
#> 1 chr7 55019032 55019033   A   G

Strandless features (TFBS) get an empty () so keys stay comparable across feature types:

func_site_key("chr7", 100, 400, ".", stranded = FALSE)
#> [1] "chr7:100-400()"

Building the sequences

Given a region and a variant inside it, PGViS extracts the region on the feature strand, applies the variant in that frame, and emits both sequences as k-mers. The substitution is deliberately forgiving about coordinates — the reference allele is searched for in a small window, because region BEDs and variant BEDs are produced by different tools and can disagree by a base — but it will not invent a result:

mutate_sequence("A", "G", "TTTATTT", pos_start = 4, pos_end = 4)  # exact
#> [1] "TTTGTTT"
mutate_sequence("A", "G", "TTTATTT", pos_start = 5, pos_end = 5)  # off by one
#> [1] "TTTGTTT"
mutate_sequence("CCCC", "G", "TTTATTT", pos_start = 4, pos_end = 7)  # wrong allele
#> [1] NA

The last returns NA rather than a plausible-looking wrong sequence. Those rows are counted and reported, and are worth investigating rather than dropping silently.

seq2kmer("ACGTACGTAC", k = 6)
#> [1] "ACGTAC CGTACG GTACGT TACGTA ACGTAC"

Population frequency resolution

UCSC’s dbSNP track packs per-project frequencies into one comma-delimited string. PGViS walks the projects in priority order and takes the first whose reported minor allele matches one of the variant’s alleles.

row <- data.frame(
  dbsnp_freqs = paste(c("0.11", "", "0.13", rep("", 9), "0.19"), collapse = ","),
  dbsnp_minor = paste(c("A",    "", "A",    rep("", 9), "A"),    collapse = ","),
  dbsnp_ref = "G", dbsnp_alt = "A"
)
pgvis_resolve_population_af(row)[, c("pop_af_alt", "pop_af_ref", "freq_source")]
#>   pop_af_alt pop_af_ref freq_source
#> 1       0.13       0.87      TOPMED

Priority is an argument, not a hard-coded cascade:

pgvis_resolve_population_af(row, priority = c("1000G", "TOPMED"))$freq_source
#> [1] "1000G"

When nothing matches, the result is NA and freq_source == "none" — not a guess.

Two things to get right

Freeze the weights when you move to a validation cohort. By default they are refit from PC1 of the data in front of you, so two runs are not on the same scale unless you say so:

w  <- attr(discovery_scores, "weights")
val <- pgvis_score(validation, weights = w)

Do not turn off ancestry stratification casually. Allele-frequency divergence from a reference panel is confounded with genetic distance from that panel. strata = NULL is available for a genuinely homogeneous cohort and is the wrong choice otherwise.

Comparing groups

d <- data.frame(pgvis = c(rnorm(120, 0), rnorm(120, 1.1)),
                group = rep(c("control", "case"), each = 120))
pgvis_compare_groups(d, min_n = 50, n_perm = 500)[, c("n1", "n2", "auc", "cohens_d", "perm_p")]
#>    n1  n2 auc cohens_d      perm_p
#> 1 120 120  NA 1.079853 0.001996008

Below min_n per group, statistics are withheld rather than reported with a caveat — an effect size from a dozen samples is not something to put on a figure.

small <- data.frame(pgvis = rnorm(20), group = rep(c("a", "b"), 10))
pgvis_compare_groups(small, min_n = 50)$label
#> [1] "N = 10 vs 10\n(below n = 50, suppressed)"
