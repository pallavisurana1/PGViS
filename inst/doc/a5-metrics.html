5. Per-variant metrics, filtering, and QC

Now we combine the model probabilities with the allele frequencies into per-variant metrics, and filter down to the variants that are both disruptive and worth scoring. This whole step runs against the bundled fixture, so every chunk here executes.

The three metrics

Each (region, variant) pair gets three numbers, capturing complementary evidence.

Log-odds ratio — how much the model’s confidence in the regulatory element drops when the variant is introduced. Positive means disruptive.

log_odds_ratio(p_ref = 0.97, p_alt = 0.03)
#> [1] 10.0299
log_odds_ratio(0.5, 0.5)          # no change -> 0
#> [1] 0

Probabilities are clamped away from 0 and 1, so a saturated prediction gives a large finite number rather than infinity — which keeps a single confident variant from poisoning a downstream mean.

Score change — a probability difference weighted by the larger of the two probabilities, so a change between two low-confidence values counts for less.

score_change(0.9, 0.7)    # confident, so the shift counts
#> [1] -0.18
score_change(0.3, 0.1)    # same 0.2 shift, but low confidence, so shrunk
#> [1] -0.06

Delta-Wi — divergence between the cohort allele frequencies and the matched population frequencies. A variant enriched in the cohort relative to the population scores high. It’s rank-based inverse-normal transformed, because the raw statistic is heavily right-skewed.

d <- data.frame(af_ref = 0.60, af_alt = 0.40,
                pop_af_ref = 0.95, pop_af_alt = 0.05)
pgvis_delta_wi(d, transform = FALSE, keep_raw = TRUE)[, c("delta_af_alt", "delta_wi")]
#>   delta_af_alt delta_wi
#> 1         0.35 7.368281

Population frequency resolution

Delta-Wi needs a population frequency, and getting it out of dbSNP is fiddly: UCSC packs each project’s frequencies into one comma-delimited string, and you have to find the project whose reported minor allele matches your variant. PGViS walks the projects in priority order.

row <- data.frame(
  dbsnp_freqs = paste(c("0.11", "", "0.13", rep("", 9), "0.19"), collapse = ","),
  dbsnp_minor = paste(c("A",    "", "A",    rep("", 9), "A"),    collapse = ","),
  dbsnp_ref = "G", dbsnp_alt = "A"
)
pgvis_resolve_population_af(row)[, c("pop_af_alt", "pop_af_ref", "freq_source")]
#>   pop_af_alt pop_af_ref freq_source
#> 1       0.13       0.87      TOPMED

The priority order is an argument, so you can prefer a different project when more than one reports a frequency:

pgvis_resolve_population_af(row, priority = c("1000G", "TOPMED"))$freq_source
#> [1] "1000G"

When no project’s minor allele matches, the result is NA and freq_source == "none" — never a guess.

Putting it together

pgvis_variant_metrics() joins the variant table to the predictions and computes all three metrics in one call.

variants <- pgvis_example("variants")
preds    <- pgvis_example("predictions")

metrics <- pgvis_variant_metrics(variants, preds)
metrics[1:3, c("feature", "log_odds_ratio", "score_change", "delta_wi_int")]
#>    feature log_odds_ratio score_change delta_wi_int
#> 1 acceptor       2.716857   -0.1655458    1.6249807
#> 2 acceptor       3.139982   -0.3735339    1.3967126
#> 3 acceptor      12.738999   -0.7603838   -0.5668246

The join is on feature, func_site and var_site — the canonical keys, so there’s no rename dance and no silent mismatch. Variants with no matching prediction are reported and dropped.

Filtering to disruptive variants

Not every scored variant is interesting. pgvis_filter_disruptive() keeps those where the model is confident the reference is functional and the mutant is not, and where enough samples carry the variant to matter.

kept <- pgvis_filter_disruptive(
  metrics,
  ref_prob_min = 0.5, alt_prob_max = 0.5, min_carrier_frac = 0
)
nrow(metrics)
#> [1] 240
nrow(kept)
#> [1] 153

It records how many rows each criterion removed, so you can see where your variants went:

attr(kept, "pgvis_filter")
#>            input after_model_prob 
#>              240              153

In a real run you’d pass cfg and let it use the configured thresholds (a strict setting uses 0.7 / 0.3) rather than spelling them out each time.

Quality control

Run pgvis_qc() before going further. It reports the things that most often turn out to be wrong: features with no variants, missing population frequencies, model probabilities that never move, and carrier counts that look like a parsing artefact.

pgvis_qc(metrics)
#> PGViS QC
#> --------
#> rows: 240 
#> n_features:              [1] 4
#> sparsest_features:            CTCF      SP1 acceptor    donor        60       60       60       60 
#> freq_source:              GnoMAD TOPMED  dbGAP      52    133     55 
#> no_population_af:        [1] 0
#> no_population_af_pct:    [1] "0.0%"
#> missing_pop_af:          [1] 0
#> missing_cohort_af:       [1] 0
#> median_prob_shift:       [1] 0.3919
#> unmoved_predictions:     [1] 0
#> degenerate_predictions:  [1] FALSE
#> carrier_range:           [1]  1 30
#> zero_carrier_variants:   [1] 0
#> delta_wi_na:             [1] 0
#> 
#> No QC warnings.

The two findings worth stopping for: a majority of variants with freq_source == "none" (a dbSNP build mismatch), and degenerate predictions (the model isn’t distinguishing anything). Both come with an explanatory warning rather than a bare number.

Cross-study replication

A variant seen in both TCGA and CPTAC is far more credible than one seen in either alone. When you’ve combined per-cohort results, this keeps only the replicated sites — required within stratum, so a smoker hit and a non-smoker hit don’t count as replicating each other.

combined <- data.frame(
  study     = c("tcga", "cptac", "tcga"),
  cancer    = "luad",
  func_site = c("f1", "f1", "f2"),
  var_site  = c("v1", "v1", "v2"),
  stringsAsFactors = FALSE
)
pgvis_filter_replicated(combined, within = "cancer", min_studies = 2)
#> [PGViS] Replication filter (>= 2 studies): 3 -> 2 rows (1 unique sites kept).
#> # A tibble: 2 x 5
#>   study cancer func_site var_site n_studies
#>   <chr> <chr>  <chr>     <chr>        <int>
#> 1 tcga  luad   f1        v1               2
#> 2 cptac luad   f1        v1               2

What can go wrong

  • Everything filtered out. Usually thresholds too strict for your data, or a QC problem upstream. The filter audit tells you which criterion did it.
  • freq_source mostly “none”. dbSNP build mismatch; the frequency-column indices in pgvis_freq_sources() are pinned to UCSC dbSnp155.
  • Metrics all NA for delta-Wi. No population frequency resolved for those variants, so there’s nothing to diverge from.
