3. Building sequences and preparing model input

For each (regulatory region, variant) pair we need the two sequences the model compares: the reference region as it appears in the genome, and the same region with the variant applied. This step builds them, and turns them into the k-mer input DNABERT expects.

The idea

The region is extracted on its own strand. The variant is applied in that frame. Both sequences come back in the orientation the models were trained on — splice models on the feature strand, TFBS models on the plus strand.

The substitution is deliberately forgiving about coordinates but strict about alleles. The region BED and the variant BED are produced by different tools whose coordinate conventions can disagree by a base, so the reference allele is searched for in a small window around its nominal position. But if the reference allele genuinely is not there, the function returns NA rather than inventing a plausible-looking wrong sequence.

mutate_sequence("A", "G", "TTTATTT", pos_start = 4, pos_end = 4)   # exact hit
#> [1] "TTTGTTT"
mutate_sequence("A", "G", "TTTATTT", pos_start = 5, pos_end = 5)   # nominal pos off by one
#> [1] "TTTGTTT"
mutate_sequence("CCCC", "G", "TTTATTT", pos_start = 4, pos_end = 7) # allele absent -> NA
#> [1] NA

That last NA is a feature. A variant whose reference allele cannot be located in the extracted region is a data problem — usually a coordinate or build mismatch — and you want it surfaced and counted, not silently scored.

Strand handling

The one genuinely fiddly bit is the minus strand: the region sequence is reverse-complemented, so a variant near the region’s end maps to a position near the mutated sequence’s start. PGViS handles this internally; the property that must hold is that a variant and its minus-strand image sit at mirror positions. For a length-L region, the plus-strand offset and the minus-strand offset sum to L + 1. (This is checked in the package’s tests.)

revcomp("ACCGGT")
#> [1] "ACCGGT"
revcomp(revcomp("ACGTTGCA"))    # round-trips
#> [1] "ACGTTGCA"

Building sequences for a whole table

pgvis_build_sequences() does the extraction, applies each variant, and emits k-mers. It needs a BSgenome object; by default the hg38 build. Because that is a large Bioconductor dependency, the chunk below is not evaluated here — but this is exactly the call you run on your own machine.

variants <- pgvis_example("variants")
seqs <- pgvis_build_sequences(
  variants,
  max_allele_len = 10,       # drop long indels the models weren't trained on
  drop_failures  = TRUE      # remove rows whose alt sequence couldn't be built
)
seqs[, c("feature", "ref_kmer", "alt_kmer")]

Failures are reported before they are dropped, so you can see how many variants had a locating problem:

[PGViS] 3/240 variants: reference allele not found in the region sequence.

If that fraction is large, stop and check your coordinate conventions before trusting anything downstream.

K-mers

DNABERT reads sequences as space-separated overlapping k-mers. The fine-tuned models in the DeepVRegulome collection use k = 6.

seq2kmer("ACGTACGTAC", k = 6)
#> [1] "ACGTAC CGTACG GTACGT TACGTA ACGTAC"

Writing model input

pgvis_write_model_input() writes one directory per feature, each containing the two files the DNABERT predictor expects: dev.tsv (alternating reference and alternate k-mers, labelled 0 and 1) and variants.tsv (the full row metadata, so predictions can be mapped back).

dirs <- pgvis_write_model_input(seqs, cfg$dirs$seq)
dirs
#> [PGViS] Wrote model input for 4 feature(s) to .../07_seq

The reference-then-alternate ordering is what lets the raw prediction array reshape cleanly into two columns in the next step. Keep the two files together; regenerating one without the other is the classic way to get an off-by-one between sequences and predictions.

What can go wrong

  • Many NA alt sequences. Coordinate or build mismatch between the region and variant BEDs. Check a few by hand with mutate_sequence().
  • Wrong BSgenome. Extracting hg38 coordinates against a hg19 genome gives real sequences that are simply the wrong ones — nothing errors. Make sure the genome object matches the build your variants were called on.
  • Editing variants.tsv or dev.tsv by hand. Don’t. The two are position-matched; the predictor and pgvis_read_predictions() both rely on that.
